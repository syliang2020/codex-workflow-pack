# 页面视觉与交互过程测试

检查静态布局、样式及交互过程中的视觉稳定性，输出参照、复现步骤和脱敏证据。可独立调用，也可接入 `development-workflow-router` 的前端 / 全栈测试阶段。

## 职责与入口

- 本 skill 不承担业务功能验收、接口正确性、持久化、权限或跨模块业务一致性测试。点击、查询、展开等操作只用于触发被测视觉状态，操作成功不能推导业务功能正确。
- 只有页面地址和账号时，可以在授权范围内检查客观重叠、遮挡、溢出和过程表现；间距、对齐及视觉一致性需要项目规范或可靠参照。参照不足时记录限制，不虚构标准。
- 用户只要求视觉测试时，不强制进入开发执行器；仅测试不自动授权修复业务代码。用户同时要求功能验收时，将其作为独立任务，先取得需求、已确认业务规则和预期结果，不用当前实现自证正确。
- 消费 router 已确认的页面、状态、窗口及权限，不重排阶段；prompt-preview 不执行，review-only 不修改代码，其他模式也不自动授权子代理。
- 先读取 [范围与页面状态](references/scope-and-states.md)、[视觉与交互检查](references/visual-and-interaction.md)；按 [证据、判定与复测](references/execution-and-evidence.md) 记录结果。

## 执行约定

1. 确定页面、版本、参照组件或同类页面、实际支持的窗口尺寸及允许的操作；只追问阻塞项。
2. 按风险选择页面 × 状态 × 窗口尺寸，覆盖受影响的正常、空态、长文本、校验提示、加载和失败表现，不机械穷举。
3. 在真实浏览器检查布局、对齐、间距、遮挡、裁切和滚动；再观察弹窗、下拉、加载、菜单折叠等过程中是否异常移位。
4. 以截图和针对性的几何信息核实静态问题；动态问题保留视频、连续截图或位置时序。最终截图不能代替过程证据。
5. 记录每项发现的参照、触发条件、实际表现、影响与证据。区分真实缺陷、合法叠层和滚动行为、无依据的审美建议。
6. 仅测试时报告缺陷；修复已获授权时交给对应实现者，复测原问题、相邻状态与窗口及共享组件影响范围。
7. 每次实际执行后必须保存本次 `REPORT.md` 并关联截图及必要的过程证据，未发现缺陷或执行受阻也须记录；按 [报告交付约定](references/execution-and-evidence.md#报告文件与交付) 核对文件与链接，最终回复提供报告链接。
8. 输出静态视觉和交互过程两类结论，不输出功能通过、完整菜单通过或系统验收通过。自动化回归脚本按需且获准后编写，不是每次测试的必选产物。

## 按需角色与 skills

先检查授权和当前工具实际可用角色；未派发时由主代理执行并说明，不编造独立测试。

| 能力 | 用途与边界 |
| --- | --- |
| `ui-ux-tester` | 浏览器视觉及过程检查，输出覆盖与缺陷证据；不改业务代码 |
| `browser-debugger` | 视觉失败难复现或原因不清时，定位 DOM、样式、滚动、层级及状态变化；不在诊断中改业务代码 |
| `test-automator` | 确有需要且已获授权时实现视觉回归脚本，限测试与必要配置，不新增未经确认依赖 |
| `qa-expert` | 多页面、多状态视觉覆盖需要策划时只读分析；普通局部检查无需额外派发 |
| `ui-fixer` / `frontend-developer` | 修复另获授权后，按局部样式或前端逻辑范围选择；不同时修改同一文件 |
| `reviewer` | 有测试或修复代码改动时只读审查，不代替真实浏览器检查 |
| `ui-ux-pro-max` | UI 规范、可访问性、体验及一致性判断；项目既有规范和组件优先，不据通用建议自动重设计 |
| `playwright-local-runtime` | Windows 本机 Playwright / MCP / wrapper 的运行时与目录约定；其他环境遵循项目配置 |
| `superpowers:systematic-debugging` | 视觉失败原因不清时验证根因，不凭截图猜测 |
| `superpowers:test-driven-development` | 获准新增视觉回归测试或修复时保留失败与通过证据 |
| `superpowers:verification-before-completion` | 核对最终证据和覆盖限制，不把未执行说成通过 |

规则不明的设计取舍由 `ui-designer` 协助，必要时用户确认；仅需记录视觉缺陷时不扩大为设计项目。`REPORT.md` 是本次测试执行记录，默认随实际执行保存，无需为此另建协作文档包；团队文档仍按用户选择复用。明确禁止落盘或只预览时遵守该限制，具体例外见报告交付约定。

## 结果契约

| 维度 | 适用范围 | 状态与证据 |
| --- | --- | --- |
| 静态视觉 | 本次页面、状态、窗口及参照 | `passed` / `failed` / `not-run`，附截图、测量或限制 |
| 交互过程的视觉稳定性 | 实际存在的加载、展开、弹窗、滚动等过程 | `passed` / `failed` / `not-run`，附过程证据；不适用时说明依据 |

任一适用项失败，本次视觉检查未通过；无失败但有适用项未执行，视觉检查未完成；全部适用项有证据通过，才报告“本次已覆盖范围的视觉检查通过”。缺少参照的一致性检查不冒充通过。功能正确性明确标注“本 skill 未验证”，不纳入视觉结论，也不把不属于本 skill 的功能任务默认列为执行失败。
