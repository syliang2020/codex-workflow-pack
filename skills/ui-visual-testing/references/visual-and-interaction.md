# 静态视觉与交互过程

## 判定依据

优先使用已确认设计稿、项目设计规范、公共组件与同类页面。没有设计稿时，先识别一个合适的参照组件或页面，记录来源与差异；参照对象本身的已知缺陷不能作为合格依据。

重叠、关键内容遮挡、非预期裁切等可直接按实际影响报告。间距、对齐、字号和密度优先对照现有 tokens、组件及同类页面，不套用无依据的统一像素值。缺乏依据的审美意见标为建议或待确认，不伪装成缺陷。

涉及 UI 规范审查、可访问性和体验判断时使用 `ui-ux-pro-max`；其通用建议服从项目已确认标准，不据此自动扩大到重设计或修改全局组件。

## 静态检查

| 区域 | 检查 | 需要区分的正常行为 |
| --- | --- | --- |
| 页面框架 | 菜单与内容区、固定头部、操作栏是否重叠或遮挡；内容能否完整到达 | 已确认的固定布局及滚动容器 |
| 查询与操作区 | 控件对齐、行列间距、按钮分组、换行及长标签；选择框和输入框的当前文字、占位符是否被裁切 | 项目已有密度和响应式规则；明确的省略和展开查看方式 |
| 表格与列表 | 表头和单元格、操作列、分页、空状态、长内容及内部滚动 | 合法固定列、内部横向滚动、明确的省略与查看方式 |
| 表单与弹窗 | 标签、必填标记、输入框文字、选择框选中项、校验文字、底部按钮和滚动可达性 | 正常弹窗遮罩、抽屉及嵌套滚动；有意的文本省略需有查看方式 |
| 浮层与反馈 | 下拉、日期选择、tooltip、通知是否被裁切或遮挡关键操作 | 正常覆盖关系，不将所有矩形相交判为错误 |

页面存在的正常、空数据、长文本、校验错误、加载及失败状态按风险选取；项目不支持的能力不强行编造用例。

## 真实交互过程

- 打开页面、切换菜单或折叠菜单，检查内容区尺寸与位置变化。
- 查询、翻页和异步加载，检查控件、表格、空状态及分页是否异常跳动。
- 打开和关闭弹窗、抽屉、下拉与日期控件，检查展开过程、边界、滚动和焦点。
- 触发表单校验和错误提示，检查文字增长是否挤压或遮挡字段及按钮。
- 滚动与改变窗口尺寸，检查固定列、操作栏和滚动条；只覆盖实际支持的设备与尺寸，不默认增加移动端要求。

正常、符合项目设计的动画和重排不自动算缺陷。对异常过程记录触发动作、时间顺序、受影响元素及连续截图、视频或位置时序；最终稳定截图不能替代过程验证。

## 工具与证据

真实浏览器观察配合定向的元素尺寸、位置、可视区域和滚动范围检查。DOM 几何信息用于确认具体假设，不能仅因两个元素边界相交就认定遮挡，也不能以没有矩形相交证明整体视觉合格。

截图差异用于已确认合格基线的持续回归。基线不存在时先审查实际页面；差异出现后解释其原因，不自动更新基线、调大容差或隐藏被测区域来消除失败。固定可比较的浏览器、窗口、字体和数据；对可变内容的遮罩不得覆盖本次被测布局。

截图断言可能等待页面稳定或关闭动画，需另保留动态过程验证。浏览器 MCP 的截图不等于已经运行截图断言。相关能力参考 [Playwright 视觉对比](https://playwright.dev/docs/test-snapshots) 和 [截图断言](https://playwright.dev/docs/api/class-pageassertions#page-assertions-to-have-screenshot-1)。
