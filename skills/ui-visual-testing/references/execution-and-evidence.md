# 视觉证据、判定与复测

## 执行记录

保留页面与版本、状态、触发步骤、参照来源、窗口尺寸与缩放、预期视觉、实际表现、结果、证据和时间。复用已有测试记录或获准的证据目录，不自动生成整套协作文档。

截图、视频、控制台和请求证据均需脱敏，不写入凭据、认证头、cookies 或完整敏感响应。

## 两类视觉结论

- 静态视觉与交互过程的视觉稳定性分别报告范围、适用性、passed / failed / not-run 和证据。
- 任一适用项 failed，视觉检查未通过；无失败但有适用项 not-run，视觉检查未完成。不适用项说明依据，不冒充 passed。
- 全部适用项有证据通过，只能声明本次已覆盖范围的视觉检查通过；功能正确性注明“本 skill 未验证”。
- 构建、接口或操作成功不能证明视觉合格；最终稳定截图不能证明交互过程合格。
- 如果同时存在独立功能测试，分别引用其需求和执行证据，保留两份结论；不能用视觉通过覆盖功能失败，也不能用功能通过覆盖视觉失败。

## 缺陷记录

每项包括页面或组件、来源分类、严重程度与影响、状态和窗口、步骤、实际与预期、参照、脱敏证据、建议负责人及复测状态。

- 区分历史问题、本次新增和扩大问题；本次新增或扩大的真实缺陷必须修复。延期项单列，不改写原始结果。
- 重叠遮挡关键内容按实际影响报告；已确认的对齐或间距偏差也记录，不因 Minor 标签豁免本次缺陷。
- 合法浮层、内部滚动和明确的文本省略按项目预期判断；无依据的审美意见列为建议，不擅自改设计。

## 修复与复测

1. 仅测试时报告缺陷。修复另获授权后，局部 UI 交给 ui-fixer，较完整前端逻辑交给 frontend-developer；若涉及业务规则或后端，交回相应开发流程，不在视觉测试中直接修复。
2. 诊断、修复与复测分别记录；不改预期、不更新基线来掩盖缺陷。
3. 可自动化时保留修复前失败与修复后通过证据；旧版本不可得时如实说明。
4. 复测原操作、数据表现和窗口，再检查长文本、错误态、相邻尺寸及共享组件受影响路径。
5. 新代码补审并验证最终版本，不能沿用旧提交的证据；清理仍遵守授权。

## 最终输出

范围与版本 → 两类视觉结论 → 缺陷及参照 → 实际执行者与证据 → 复测 → 未覆盖、阻塞和风险。明确“业务功能正确性未由本 skill 验证”。

示例：静态视觉 failed（弹窗按钮遮挡字段），交互过程 not-run，则视觉检查未通过。即使保存操作成功，也不输出业务功能 passed 或完整菜单验收通过。
