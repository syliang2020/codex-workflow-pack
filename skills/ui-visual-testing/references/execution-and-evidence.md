# 执行与证据

读取时机：已经开始实际视觉检查、需要判定结果、记录缺陷或复测时读取。

## 执行记录

记录页面与版本、状态、触发步骤、参照、窗口与缩放、预期视觉、实际表现、结果、证据和时间。截图、视频、控制台和请求证据必须脱敏。

真实检查以浏览器操作为准。浏览器 MCP 能截图不等于项目已有 Playwright Test 截图断言能力；不要把静态文档检查、接口成功或模拟响应当作真实页面证据。

## 自动化与环境

复用项目已有浏览器工具、测试框架、脚本和 fixtures，不擅自新增依赖或迁移框架。获准编写回归脚本时，仅修改视觉测试及必要配置，注明环境、命令、基线和副作用。缺少环境时标记 `not-run`，不以本地样例或静态文档检查代替真实页面执行。清理测试数据、证据和临时文件遵守删除确认规则。

## 两类视觉结论

- **静态视觉**：布局、对齐、间距、遮挡、裁切、溢出、表格、弹窗、浮层和空态。
- **交互过程视觉稳定性**：加载、展开、折叠菜单、弹窗、下拉、滚动、窗口变化和错误提示出现过程。

两类结论分别使用 `passed`、`failed` 或 `not-run`。任一适用项 `failed`，视觉检查未通过；无失败但有适用项 `not-run`，视觉检查未完成；不适用项说明理由。报告必须明确“业务功能正确性未由本 skill 验证”。

## 缺陷与复测

每项缺陷记录页面或组件、来源、严重程度与影响、窗口和状态、步骤、实际与预期、参照、脱敏证据、负责人和复测状态。

- 区分历史问题、本次新增和本次扩大问题。本次新增或扩大的真实视觉缺陷必须修复，不能因 Minor 延后。
- 合法浮层、内部滚动和明确的文本省略按项目预期判断；无参照的“更好看”列为设计建议。
- 复测原操作、同一数据状态和窗口，再检查长文本、错误态、相邻尺寸及共享组件。
- 有新代码时补审并验证最终版本；不能沿用旧版本证据。

## 报告交付

实际执行结束或因故停止时，读取 [报告模板](report-template.md) 并保存 UTF-8 中文 `REPORT.md`。报告目录优先遵从用户指定位置，其次使用项目已有测试输出目录；本机 Playwright 遵守 `playwright-local-runtime` 的输出路径。

报告以相对链接关联本次运行的截图和过程证据，不覆盖旧运行。未发现缺陷、环境阻塞和部分执行同样要保存报告。最终回复提供绝对路径的报告链接；只预览、明确禁止落盘或无获准写入目录时，说明报告未保存及原因，不伪造文件。
