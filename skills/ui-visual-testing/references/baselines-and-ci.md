# 截图基线与 CI

读取时机：用户明确要求截图回归、像素差异、基线审批或 CI 阻断时读取。

## Playwright 截图基线

复用项目已有 Playwright Test 配置。基线必须在固定浏览器、操作系统、字体、viewport、数据和运行模式下生成；首次生成的基线必须人工审查后提交。基线更新必须作为单独的可审查变更，不能用 `--update-snapshots` 隐藏未解释的差异。

建议把截图测试拆成稳定状态和动态状态：稳定状态使用 `expect(page).toHaveScreenshot()`；动态过程继续使用位置采样、连续截图或视频。对时间、随机数据和用户信息使用经过审查的遮罩，不得遮盖被测布局。

## 阈值与分类

- 关键内容遮挡、非预期横向溢出、关键控件不可见：自动阻断候选。
- 截图差异、间距变化、字体渲染差异：生成 diff 并人工复核，不能默认阻断。
- 业务需求、接口、权限和数据库结果：交给独立功能测试，不能由截图通过替代。

## CI 接入

CI 至少固定浏览器和 viewport，保存 actual、expected、diff、扫描 JSON 和 `REPORT.md`。失败时阻止合并或进入人工审批，具体门禁由项目配置决定。不要在通用 skill 中写死 GitHub Actions、runner 或项目启动命令。

CI 不覆盖页面清单之外的状态。使用页面 × 状态 × viewport 矩阵记录覆盖率；新增页面或状态时先补矩阵和基线，再把它纳入持续检查。
