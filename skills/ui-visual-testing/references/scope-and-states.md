# 范围与页面状态

## 最小输入

- 待检查页面、组件及排除范围；已有系统按指定菜单抽样，增量改动按受影响路径检查。
- 可访问环境、版本、账号及允许的操作；凭据仅用于登录，不写入脚本、报告或仓库。
- 视觉预期来源：已确认设计稿、项目规范、公共组件或可靠的同类页面；参照自身的已知缺陷不能作为合格标准。
- 实际支持的窗口尺寸、缩放及设备；没有依据时不默认增加移动端要求。

客观遮挡、裁切等问题可先观察；无法确认间距或一致性标准时，查找项目已有资料或请用户指定参照，相关检查保留限制。无需为了纯视觉检查强制索要完整业务需求。

## 页面状态矩阵

记录页面 / 组件、状态、触发动作、数据表现、角色、窗口尺寸、参照、预期视觉、结果和证据。优先覆盖：

- 正常内容、空数据、长文本、较多标签等会影响布局的表现。
- 表单校验文字、错误提示、加载和失败状态。
- 弹窗、抽屉、下拉、固定列、菜单折叠、滚动和尺寸变化。
- 共享组件和相邻窗口的回归影响。

选择有风险的代表案例，不把抽样说成所有页面或状态均已检查。纯后端任务不进入本 skill。

## 操作与数据边界

- 点击、查询、切换和展开用于呈现被测状态，只记录视觉表现，不据此宣布筛选规则、必填规则、权限或数据正确。
- 优先使用现有测试数据及可逆操作；需真实保存、删除或其他写入才能形成状态时，先核对授权，不能因测试而默认获得数据变更权限。
- 若使用模拟或拦截响应形成视觉状态，明确标记，不能作为真实接口或功能验收证据。
- 导航后核对实际页面和登录态。跳回登录页、无权限页或错误页时记录阻塞，不把其截图当目标页证据。
- 如用户另要求功能测试，须有“需求来源 → 前置条件与数据 → 操作 → 已确认预期”的独立用例。当前源码、页面和接口行为只能帮助理解实现，不能独立证明业务正确；该任务不由本 skill 承担。
