# Review And Handoff Rules

## 子代理交接规则

每个子代理完成任务后，必须输出交接报告：

1. 完成内容
2. 修改文件清单
3. 测试命令
4. 测试结果
5. 未完成项
6. 风险点
7. 是否存在计划外修改
8. 是否需要主 agent 继续处理

不得编造子代理已经执行的检查、测试或结论。

## 主 agent 回收规则

主 agent 回收子代理后，必须检查：

1. `git status`
2. `git diff`
3. 构建结果
4. 测试结果
5. 是否符合 `writing-plans`
6. 是否有计划外修改
7. 是否存在前后端接口不一致
8. 是否存在未处理 TODO 或临时 mock

## 审查规则

后端审查：

- 优先使用 `backend-feature-design-review` skill，并可按需启动 `reviewer` subagent 做 PR 风格审查。
- 检查接口契约、分层、事务、权限、异常、分页、数据一致性、幂等性。
- 如果审查子代理不可用，主 agent 必须执行同等检查。

前端审查：

- 优先使用 `ui-ux-pro-max` skill，并可按需启动 `reviewer` 或 `ui-fixer` subagent。
- 检查交互、状态、表单校验、接口调用、错误提示、权限展示、加载态、空状态。
- 如果审查子代理不可用，主 agent 必须执行同等检查。

## 只读审查规则

用户要求只读审查时：

1. 不修改文件。
2. 不进入 `executing-plans`。
3. 不启动实现型子代理。
4. 可按只读边界启动 `reviewer`、`api-designer`、`sql-pro`、`debugger` 或 `security-auditor`。
5. 输出必须区分历史问题、本次新增问题、本次修改扩大历史问题。
6. 本次新增或扩大的问题必须标为需要修复；不能标成历史遗留。

## 测试结果记录

测试结果必须标记为：

- `passed`：测试通过。
- `failed`：测试失败，必须修复后重跑。
- `not-run`：未运行，必须说明原因。

如果测试失败：

1. 不得直接进入验收。
2. 必须定位失败原因。
3. 如果是本次改动导致，必须修复。
4. 如果是历史遗留问题，必须说明证据和影响。
5. 最终验收报告必须包含测试状态。

## 验收报告

最终必须输出：

1. 完成功能
2. 修改文件
3. 数据库变更
4. 接口清单
5. 前端页面清单
6. 测试结果
7. Playwright 或浏览器测试结果
8. 已知风险
9. 后续建议
