# Testing Checklist

适用于开发、修复、联调和验收阶段。

## 测试类型

根据任务选择：

1. 编译检查。
2. 单元测试。
3. 接口测试。
4. 前端构建测试。
5. 类型检查。
6. Lint 检查。
7. 前后端联调。
8. Playwright 或浏览器真实测试。
9. 回归测试。

## 测试结果状态

每个测试必须标记为：

- `passed`：测试通过。
- `failed`：测试失败。
- `not-run`：未运行。

## failed 处理

如果测试失败：

1. 不得直接进入验收。
2. 必须定位失败原因。
3. 如果是本次改动导致，必须修复并重跑。
4. 如果是历史遗留问题，必须说明证据和影响。
5. 验收报告必须记录失败项和处理结论。

## not-run 处理

如果测试未运行：

1. 必须说明未运行原因。
2. 必须说明风险。
3. 必须给出用户可执行的验证命令。
4. 不得把 `not-run` 描述成 `passed`。
