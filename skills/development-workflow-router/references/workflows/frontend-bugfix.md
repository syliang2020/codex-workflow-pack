# Frontend Bugfix Workflow

前端 bugfix 用于问题边界主要在页面渲染、交互、样式、状态管理、前端路由或前端测试失败的场景。只要问题依赖后端接口、字段、权限或数据口径变化，必须考虑 `fullstack-bugfix`。

## 阶段

### 1. Bug 复现与系统化调试

- 使用：
  - `superpowers:systematic-debugging`
  - `debugger`
  - `playwright-local-runtime`（需要真实浏览器复现时）
- 输入：
  - 用户描述
  - 页面路径
  - 报错信息
  - 失败测试
  - 浏览器现象
- 输出：
  - 可复现步骤
  - 实际现象
  - 期望现象
  - 影响范围
  - 初步根因假设
- 是否允许改代码：否。
- 是否需要用户确认：复现信息不足、页面路径不明确或影响范围不清时需要确认。
- 执行要求：
  - 不得跳过 bug-reproduce。
  - 需要真实浏览器时必须使用 Playwright 或项目认可的浏览器验证方式。

---

### 2. 根因定位

- 使用：
  - `superpowers:systematic-debugging`
  - `debugger`
  - `ui-fixer`
- 输入：
  - 复现结果
  - 相关前端代码
  - 控制台、网络请求和 UI 状态
- 输出：
  - 已验证根因
  - 受影响组件或页面
  - 是否涉及后端接口
  - 回归风险
- 是否允许改代码：否。
- 是否需要用户确认：根因不唯一、需要后端改动或修复会改变交互行为时需要确认。
- 执行要求：
  - 如果发现需要后端改动，必须改判为 `fullstack-bugfix`。
  - 修复会改变业务行为时，必须补充 `superpowers:brainstorming`。

---

### 3. 修复方案设计

- 使用：
  - `ui-ux-pro-max`
  - `api-designer`
- 输入：
  - 已验证根因
  - 受影响页面、组件、状态和接口调用
  - 现有 UI/UX 规则
- 输出：
  - 修复方案
  - UI/UX 风险
  - 接口依赖结论
  - 回归测试点
- 是否允许改代码：否。
- 是否需要用户确认：修复影响交互、视觉、接口依赖或用户路径时需要确认。
- 执行要求：
  - `ui-ux-pro-max` 用于修复方案的 UI/UX 检查。
  - 涉及接口契约时使用 `api-designer`；若需要后端变更，改判为 `fullstack-bugfix`。

---

### 4. `superpowers:writing-plans`

- 使用：
  - `superpowers:writing-plans`
- 输入：
  - 根因定位结果
  - 修复方案
  - 回归测试点
  - 项目前端构建和测试约束
- 输出：
  - 文件级修复计划
  - 回归测试计划
  - 浏览器验证计划
  - 风险和回滚方案
  - 子代理分工计划
- 是否允许改代码：否。
- 是否需要用户确认：是，计划未确认前不得实现。
- 执行要求：
  - 计划必须体现 `superpowers:executing-plans with TDD` 或前端回归测试策略。

---

### 5. 用户确认

- 使用：
  - 主 agent
- 输入：
  - 修复计划
  - 风险和回归测试点
- 输出：
  - 用户确认结果
  - 需要调整的计划
- 是否允许改代码：否。
- 是否需要用户确认：是。
- 执行要求：
  - 用户未确认前不得修改代码或启动实现型 subagent。

---

### 6. `superpowers:executing-plans` with TDD

- 使用：
  - `superpowers:executing-plans`
  - `frontend-developer`
  - `ui-fixer`
- 输入：
  - 已确认的修复计划
  - 回归测试计划
  - 可修改范围
- 输出：
  - 前端修复
  - 回归测试或验证脚本
  - 实际修改文件
  - 偏离计划的说明
- 是否允许改代码：是，仅限用户确认后的计划范围。
- 是否需要用户确认：进入本阶段前需要确认；偏离计划时需要再次确认。
- 执行要求：
  - 能先补复现问题的失败测试或浏览器验证脚本时，先补测试再修复。
  - 前端修复优先交给 `frontend-developer` 或 `ui-fixer`；不可用时主 agent 替代并说明。

---

### 7. 子代理交接与回收

- 使用：
  - 主 agent
  - 已启动的 subagents
  - `references/review-and-handoff.md`
- 输入：
  - subagent 交付结果
  - 修复 diff
  - 浏览器或测试输出
- 输出：
  - 子代理交接摘要
  - 根因修复核对
  - 主 agent 回收结论
- 是否允许改代码：必要时允许，但只能处理集成缺口和冲突。
- 是否需要用户确认：交接结果改变计划或风险升高时需要确认。
- 执行要求：
  - 未启动的计划内 subagent 必须说明原因并给出主 agent 替代产出。

---

### 8. 代码审查

- 使用：
  - `ui-ux-pro-max`
  - `reviewer`
- 输入：
  - 当前 diff
  - 根因和修复方案
  - 回归测试或浏览器验证计划
- 输出：
  - UI/UX 审查结果
  - 通用代码审查结果
  - 历史问题 / 本次新增问题 / 本次扩大问题分类
  - 必须修复项
- 是否允许改代码：审查阶段默认否；发现本次新增阻塞问题后，回到执行阶段修复。
- 是否需要用户确认：涉及范围扩大或交互取舍时需要确认。
- 执行要求：
  - 必须检查布局、响应式、文本溢出、交互状态和真实浏览器路径。

---

### 9. 回归测试与真实浏览器验证

- 使用：
  - 项目前端测试命令
  - `playwright-local-runtime`
  - `superpowers:verification-before-completion`
- 输入：
  - 修复后的代码
  - 回归测试计划
  - 页面复现路径
- 输出：
  - 实际运行命令
  - 构建或测试结果
  - Playwright / 浏览器验证结果
  - 未覆盖点
  - 无法运行时的原因和替代验证
- 是否允许改代码：发现问题时回到执行阶段修复。
- 是否需要用户确认：测试无法运行、需要替代验证或风险较高时需要确认。
- 执行要求：
  - 必须证明原前端问题已修复或解释无法证明的原因。
  - 不得伪造测试结果。

---

### 10. 验收

- 使用：
  - 主 agent
  - acceptance checklist
- 输入：
  - 最终 diff
  - 回归测试和浏览器验证结果
  - 审查结果
- 输出：
  - 修复摘要
  - 修改文件
  - 验证命令和结果
  - 剩余风险
  - 建议验收路径
  - 实际使用的 skills / subagents / 替代执行说明
- 是否允许改代码：否。
- 是否需要用户确认：由用户最终验收。
- 执行要求：
  - 最终说明必须包含 bug 复现、根因、修复和浏览器验证证据。
