# Frontend Feature Workflow

前端功能只在不需要新增或修改后端接口、数据库、权限、服务端业务规则时使用。只要页面需要调用新接口、调整接口字段或依赖后端联调，必须改判为 `fullstack-feature`。

## 阶段

### 1. `superpowers:brainstorming`

- 使用：
  - `superpowers:brainstorming`
- 输入：
  - 用户原始需求
  - 目标用户和使用场景
  - 现有页面、组件和交互约束
- 输出：
  - 需求目标
  - 页面或组件范围
  - 不做范围
  - 状态、交互和验收标准
  - 待确认问题
- 是否允许改代码：否。
- 是否需要用户确认：是，交互或范围不清时必须确认。
- 执行要求：
  - 不得直接进入 UI 实现。
  - 必须明确真实浏览器验证是否需要。

---

### 2. UI / 交互设计

- 使用：
  - `ui-designer`
  - `ui-ux-pro-max`
- 输入：
  - brainstorming 结论
  - 现有设计系统、组件、样式和页面结构
  - 响应式和可访问性约束
- 输出：
  - UI 方案
  - 组件拆分建议
  - 状态和交互说明
  - 响应式与可访问性检查点
- 是否允许改代码：否。
- 是否需要用户确认：视觉、交互或用户路径有取舍时需要确认。
- 执行要求：
  - `ui-designer` 负责体验和结构方案。
  - `ui-ux-pro-max` 负责 UI/UX 检查标准和可访问性要求。
  - subagent 或 skill 不可用时，主 agent 必须说明原因并替代完成。

---

### 3. 接口依赖确认

- 使用：
  - `api-designer`
- 输入：
  - 前端数据需求
  - 现有 API 调用方式
  - 字段来源和兼容性要求
- 输出：
  - 复用现有接口的结论
  - 是否需要后端改动
  - 前端 mock 或降级方案
- 是否允许改代码：否。
- 是否需要用户确认：如果发现需要后端改动，必须确认并改判为 `fullstack-feature`。
- 执行要求：
  - 不得在前端侧硬编码绕过缺失接口。
  - 不得把后端字段语义不清的问题留到实现阶段。

---

### 4. `superpowers:writing-plans`

- 使用：
  - `superpowers:writing-plans`
- 输入：
  - 已确认的 UI / 交互方案
  - 接口依赖确认结果
  - 项目前端构建和测试约束
- 输出：
  - 文件级实现计划
  - 组件和状态管理计划
  - 测试和 Playwright 验证计划
  - 风险和回滚方案
  - 子代理分工计划
- 是否允许改代码：否。
- 是否需要用户确认：是，计划未确认前不得实现。
- 执行要求：
  - 计划必须体现 `superpowers:executing-plans with TDD` 或前端回归测试策略。
  - 计划必须写清楚真实浏览器验收路径。

---

### 5. 用户确认

- 使用：
  - 主 agent
- 输入：
  - `writing-plans` 输出
  - UI / 接口依赖结论
- 输出：
  - 用户确认结果
  - 需要调整的设计或计划
- 是否允许改代码：否。
- 是否需要用户确认：是。
- 执行要求：
  - 用户未确认前不得修改代码或启动实现型 subagent。

---

### 6. `superpowers:executing-plans` with TDD

- 使用：
  - `superpowers:executing-plans`
  - `frontend-developer`
- 输入：
  - 已确认的计划
  - UI / 交互方案
  - 测试计划
- 输出：
  - 前端实现
  - 新增或调整的测试
  - 实际修改文件
  - 偏离计划的说明
- 是否允许改代码：是，仅限用户确认后的计划范围。
- 是否需要用户确认：进入本阶段前需要确认；偏离计划时需要再次确认。
- 执行要求：
  - 能先补组件测试、状态测试或回归用例时，先补测试再实现。
  - 前端实现优先交给 `frontend-developer`；不可用时由主 agent 替代并说明原因。

---

### 7. 子代理交接与集成回收

- 使用：
  - 主 agent
  - 已启动的 subagents
  - `references/review-and-handoff.md`
- 输入：
  - subagent 交付结果
  - 实际修改文件
  - 本地运行和测试结果
- 输出：
  - 子代理交接摘要
  - UI / 状态 / 接口调用缺口
  - 主 agent 集成结论
- 是否允许改代码：必要时允许，但只能处理集成缺口和冲突。
- 是否需要用户确认：交接结果改变计划或风险上升时需要确认。
- 执行要求：
  - 未启动的计划内 subagent 必须说明原因和主 agent 替代产出。

---

### 8. 代码审查

- 使用：
  - `ui-ux-pro-max`
  - `reviewer`
- 输入：
  - 当前 diff
  - UI / 交互方案
  - 项目规则
  - 测试计划
- 输出：
  - UI/UX 审查结果
  - 通用代码审查结果
  - 必须修复项
  - 历史问题 / 本次新增问题 / 本次扩大问题分类
- 是否允许改代码：审查阶段默认否；发现本次新增阻塞问题后，回到执行阶段修复。
- 是否需要用户确认：涉及范围扩大或交互取舍时需要确认。
- 执行要求：
  - 必须检查布局、响应式、可访问性、状态反馈、文本溢出和真实交互路径。

---

### 9. 测试与真实浏览器验证

- 使用：
  - 项目前端测试命令
  - `playwright-local-runtime`
  - `superpowers:verification-before-completion`
- 输入：
  - 修改后的前端代码
  - 测试计划
  - 页面或组件验收路径
- 输出：
  - 实际运行命令
  - 构建或测试结果
  - Playwright / 浏览器验证结果
  - 截图或关键观察
  - 未覆盖点
- 是否允许改代码：发现问题时回到执行阶段修复。
- 是否需要用户确认：测试无法运行、需要替代验证或风险较高时需要确认。
- 执行要求：
  - 涉及可视页面或交互时必须进行真实浏览器验证。
  - 不得伪造测试结果。

---

### 10. 验收

- 使用：
  - 主 agent
  - acceptance checklist
- 输入：
  - 最终 diff
  - 测试与浏览器验证结果
  - 审查结果
- 输出：
  - 变更摘要
  - 修改文件
  - 验证命令和结果
  - 剩余风险
  - 建议验收路径
  - 实际使用的 skills / subagents / 替代执行说明
- 是否允许改代码：否。
- 是否需要用户确认：由用户最终验收。
- 执行要求：
  - 最终说明必须包含浏览器验证是否完成，以及未完成时的原因。
