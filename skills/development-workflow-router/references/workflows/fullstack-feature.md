# Fullstack Feature Workflow

适用于前端和后端一起开发的完整功能。只要用户明确提到前后端、接口和页面、后端加接口前端对接、页面调用新接口，默认使用本 workflow。

## 标准流程

### 1. `superpowers:brainstorming`

- 使用：
  - `superpowers:brainstorming`
- 输入：
  - 用户需求
  - 项目上下文
  - 现有前端页面和后端接口
- 目标：
  - 澄清业务目标、前后端边界、数据流、权限、影响范围和验收标准
- 输出：
  - 业务目标
  - 前端范围
  - 后端范围
  - 数据流
  - 权限影响
  - 不做事项
  - 验收标准初稿
  - 需要用户确认的问题
- 是否允许改代码：
  - 否
- 是否需要用户确认：
  - 是

---

### 2. `api-designer` / `sql-pro` / `ui-designer` 协同设计

- 使用：
  - `api-designer`
  - `sql-pro`
  - `ui-designer`
  - `ui-ux-pro-max`
  - `feature-doc-pack`（需要协作文档时先询问用户）
- 输入：
  - 已确认的 brainstorm 结果
  - 现有 API、表结构、页面、组件和调用链
  - 字段语义、权限、状态和历史兼容要求
- 目标：
  - 定义接口契约
  - 判断数据库影响，涉及结构变更时输出 DDL 草案
  - 定义 UI 交互边界
  - 对齐数据库、接口和 UI
- 输出：
  - API 契约草案
  - 数据库影响说明
  - UI / 交互方案
  - 前后端字段映射
  - 联调和验收口径
  - 协作文档需求判断
- 是否允许改代码：
  - 否
- 是否需要用户确认：
  - 涉及接口兼容、数据库结构、字段语义、UI 取舍或协作文档时需要确认

---

### 3. 设计门禁 review

- 使用：
  - `backend-feature-design-review`
  - `ui-ux-pro-max`
- 输入：
  - 协同设计结果
  - API 契约草案
  - 数据库影响说明
  - UI / 交互方案
  - 计划修改的模块和文件范围
- 目标：
  - 审查后端接口、数据库、分层、权限、异常和事务
  - 审查 UI 交互方案
- 输出：
  - 后端设计审查结论
  - UI/UX 设计审查结论
  - 阻塞问题和修正建议
  - 前后端联调风险
- 是否允许改代码：
  - 否
- 是否需要用户确认：
  - 审查不通过、存在设计取舍或风险上升时需要确认

---

### 4. `superpowers:writing-plans`

- 使用：
  - `superpowers:writing-plans`
- 输入：
  - 已确认的需求、接口契约、数据库方案、UI 方案和设计审查结果
  - 项目构建、测试和启动约束
- 目标：
  - 生成前端、后端、联调、测试和验收任务计划
- 输出：
  - 前后端文件级修改清单
  - 实现步骤
  - 联调计划
  - 测试与 Playwright 验证计划
  - 子代理分工，如需要
  - 风险和回滚方案
- 是否允许改代码：
  - 否
- 是否需要用户确认：
  - 是，计划确认前不得写代码

---

### 5. `superpowers:executing-plans` with TDD

- 使用：
  - `superpowers:executing-plans`
  - `spring-boot-engineer`
  - `frontend-developer`
- 输入：
  - 已确认的 writing-plans
  - 接口契约、数据库方案和 UI 方案
  - 测试和联调计划
- 目标：
  - 后端先写失败测试，再实现，再跑测试
  - 前端补必要回归用例或浏览器验证路径
  - 前后端可以并行，但不得修改同一文件或互相覆盖契约
- 输出：
  - 后端实现
  - 前端实现
  - 新增或调整的测试
  - 实际修改文件
  - 子代理交接报告
- 是否允许改代码：
  - 是，仅限用户确认后的计划范围
- 是否需要用户确认：
  - 执行前必须已经确认 writing-plans；偏离计划时需要再次确认

---

### 6. 代码审查

- 使用：
  - `backend-feature-design-review`
  - `ui-ux-pro-max`
  - `reviewer`
- 输入：
  - 当前 diff
  - 协同设计结果
  - writing-plans
  - 测试和联调结果
- 目标：
  - 审查后端代码、前端代码、接口契约和计划外修改
- 输出：
  - 后端代码审查结论
  - UI/UX 审查结论
  - 通用代码审查结论
  - 必须修复项
- 是否允许改代码：
  - 审查阶段不改代码；不通过则回到 executing-plans 修改
- 是否需要用户确认：
  - 涉及范围扩大或取舍时需要确认

---

### 7. 联调

- 使用：
  - 主 agent
  - `api-designer`（接口契约存在疑问时）
- 输入：
  - 前后端实现
  - API 契约和字段映射
  - 错误处理和权限规则
- 目标：
  - 检查前端传参、后端返回、字段命名、状态码、错误提示和权限边界
- 输出：
  - 联调结论
  - 前后端不一致问题，如有
  - 需要回到对应端修复的问题
- 是否允许改代码：
  - 不通过时回到对应端 executing-plans 修复
- 是否需要用户确认：
  - 联调问题改变设计或范围时需要确认

---

### 8. Playwright / 浏览器真实测试

- 使用：
  - `playwright-local-runtime`
  - 项目测试命令
  - `superpowers:verification-before-completion`
- 输入：
  - 已联调的前后端功能
  - 主业务路径
  - 测试计划
- 目标：
  - 覆盖主业务路径
  - 验证真实页面和接口联动
- 输出：
  - 测试命令
  - 测试结果：`passed` / `failed` / `not-run`
  - 浏览器验证结果
  - 失败或未运行说明
- 是否允许改代码：
  - failed 且确认是本次改动导致时，回到 executing-plans 修复
- 是否需要用户确认：
  - 验收前需要给出测试结果；not-run 必须确认风险

---

### 9. 验收总结

- 使用：
  - `superpowers:verification-before-completion`
  - acceptance checklist
- 输入：
  - 最终 diff
  - 测试、联调和浏览器验证结果
  - 审查结果
- 目标：
  - 汇总全栈交付内容和验收路径
- 输出：
  - 接口清单
  - 页面清单
  - 数据库变更说明，如有
  - 修改文件
  - 测试结果
  - 浏览器验证结果
  - 已知风险
  - 回滚建议
  - 后续建议
- 是否允许改代码：
  - 否
- 是否需要用户确认：
  - 是
