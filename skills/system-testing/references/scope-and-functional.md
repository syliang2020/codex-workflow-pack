# 测试范围与功能

## 最小输入

- 本次功能、菜单或模块范围，及明确排除的内容。
- 可访问环境、运行版本或提交、启动方式；凭据仅用于登录，不写入脚本、报告和仓库。
- 用户角色、权限、可用测试数据，以及允许的新增、编辑、删除等数据操作。
- 业务规则、接口契约和验收标准；无文档时使用已确认的对话输入，不虚构规则。
- 页面任务的现有组件、同类页面或已确认设计稿，以及项目实际支持的窗口尺寸。

输入不足时先检查现有资料；只追问阻塞项，其余已具备条件的检查继续。不擅自把整个系统纳入一个局部任务。

导航或操作后核对实际页面和登录状态；跳回登录页、无权限页或错误页时，记录阻塞及受影响用例，不把该页面截图当作目标页面证据，也不继续等待原页面控件后宣称测试通过。

## 测试矩阵

按风险组织范围，至少记录：页面 / 接口、操作、角色、数据或状态、窗口尺寸（页面适用）、预期依据、自动化或人工执行方式、结果和证据。

- 增量测试：本次变化、直接调用方、共享组件和受影响的邻近路径。
- 系统验收：指定菜单、跨模块数据流和关键角色；逐项说明覆盖、阻塞和排除项。
- 同一组件的等价场景可选代表案例；不要以抽样冒充所有菜单或所有状态都已检查。

## 功能检查

1. 页面入口、路由及角色可见性，查询、筛选、排序、分页等已有能力。
2. 正常数据、空数据、边界值、长文本、无权限、接口错误和失败恢复。
3. 保存、编辑等操作的参数与返回、提示、列表或详情刷新；必要时核对持久化状态和下游展示。
4. 已确认规则要求的重复提交、状态变化、并发或跨模块一致性；没有需求依据时不擅自增加限制。
5. 回归检查既有接口契约和调用方；纯前端改动不擅自修改后端规则。

数据库检查使用项目允许的连接与范围；不得执行未授权 DDL、清库或生产数据修改。无法验证持久化状态时，说明仅覆盖页面或接口层。

## 测试数据与自动化

- 优先复用既有账号、fixtures、构建和测试命令，明确数据准备与恢复责任。
- 使用专门测试数据，执行前确认真实写入范围；删除测试记录仍遵守适用的删除确认规则。
- 自动化断言业务行为和外部契约，不只断言 mock 被调用或实现细节。
- 新增脚本注明测试目录、必要配置、运行命令、环境假设和数据副作用；不扩大到业务代码或框架迁移。
- 浏览器工具、测试运行器和截图断言能力分别核实，不把浏览器 MCP 存在等同于项目已安装 Playwright Test。
- 缺少环境或依赖时保留可执行建议与 `not-run` 原因；未经确认不安装依赖，不把模拟或本地样例结果当作真实系统验证。
