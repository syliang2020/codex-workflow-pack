# 数据访问与分页

用于自定义 SQL、MyBatis / MyBatis-Plus、关联查询、查询次数和分页审查。先确认项目真实技术栈，XML 规则只用于 MyBatis 项目，不要求 JPA、JdbcTemplate 等改用 XML。

## MyBatis SQL 组织

- 自定义 SQL 写在对应 Mapper XML 中，通过具名 DAO 方法调用；不使用 `@Select`、`@Update`、`@Insert`、`@Delete` 等 SQL 注解。
- 复杂查询及显式更新写 XML SQL，不在业务层大量拼装 QueryWrapper、UpdateWrapper 或字符串条件。
- 条件直接写在对应语句中，不为少量重复拆出多层 `<include>` 或隐式 SQL 片段，使维护者必须跳转多个定义才能理解条件。
- 参数使用绑定方式。动态列、排序和其他不能绑定的标识符必须有明确白名单，不能拼接前端原始输入。
- Mapper 的字段别名、结果映射与返回对象一致；区分关联主键和实体主键，避免联表映射覆盖字段。
- 显式检查空集合、NULL 更新和逻辑删除语义；例如清空可选字段时，SQL 必须能实际写入 NULL。

## 查询次数与结果规模

- 展示需要的关联字段和筛选条件优先由联表查询一次取得；避免循环内逐条查询以及先收集 ID、再查其他表、最后在内存补齐展示字段。
- 检查调用方间接调用的查询，不能只看当前方法是否有 DAO 调用。查询次数不应随列表行数线性增长。
- 联表前明确一对一、一对多关系；防止重复行放大分页总数，不能用 DISTINCT 盲目掩盖错误关系。
- 复用本次请求内已经读取的稳定资料，避免重复解析字典或查询基础资料；可变化的授权和状态必须按写入一致性要求复核，不能把性能优化变成陈旧状态判断。
- 对确实无法联表的外部资源或不同数据源，说明原因，采用有界批量读取并明确调用次数；不要伪造跨库联表方案。
- 只查询需要的字段，结合实际数据规模、索引和执行计划判断性能，不依据代码短或 SQL 长认定优劣。

## 分页

- 使用项目已有分页插件、参数和返回结构，不自行实现内存分页或复制一套分页框架。
- 筛选、排序及权限范围在分页前完成；列表和依赖列表取数的下游功能使用一致的数据范围。
- 不擅自新增分页上限，不静默截断、修正调用方的分页大小。已有明确的产品或项目限制按既定契约执行。
- 总数计算与数据查询口径一致，排序具备已确认的稳定兜底字段。
- 检查分页插件的线程状态和异常清理，避免无关查询误用分页或影响后续请求。

## 过滤与边界

- 校验、权限、默认过滤和字段限制必须追溯到已确认需求、数据模型或项目规则。
- 不因个人习惯新增租户、字符比较、状态或其他业务前置限制，也不擅自删除项目已要求的隔离条件。
- 数据库查询仍由所属 DAO 执行；跨领域业务规则由对应 Service 决定，不能通过注入其他领域 DAO 绕过。

## 报告证据

问题至少给出调用链、查询次数或结果放大方式、触发数据规模、正确筛选/排序/分页口径和验证办法。需要执行计划、索引或数据库确认但无法获取时，明确标为未验证，不直接声称慢查询已复现。
