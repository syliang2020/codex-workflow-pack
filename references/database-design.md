# Database Design

用于需求涉及数据库变更时，生成或更新 `DATABASE-DESIGN.md`。

`DATABASE-DESIGN.md` 是 feature-doc-pack 阶段的数据库设计草案，用于团队评审和后端分工。它不默认输出最终可执行 DDL；最终表结构和 DDL 应由后端负责人在技术设计阶段确认，除非用户明确要求在当前阶段输出。

## 触发条件

本次需求涉及以下任一情况时，必须生成或更新 `DATABASE-DESIGN.md`：

- 新增数据表
- 修改已有表结构
- 新增字段
- 修改字段类型、长度、含义或约束
- 新增索引或唯一约束
- 修改数据关系
- 新增字典表或枚举映射
- 涉及数据迁移
- 涉及历史数据兼容
- 涉及统计口径落库
- 涉及导入、导出、成绩、订单、资源等需要持久化的数据结构

## Rule Placement

- `PLAN.md`：写数据库变更摘要、范围影响和待确认项。
- `BUSINESS-RULES.md`：写字段业务含义、写入时机、查询口径、优先级和边界；不写 DDL、索引、迁移 SQL、回填 SQL 或回滚 SQL。
- `API-CONTRACT.md`：写接口字段语义、请求响应结构和必要的数据映射；不写数据库迁移脚本。
- `DATABASE-DESIGN.md`：写数据模型和数据库设计草案，包括表清单、字段草案、关系、约束、索引建议、字典映射、迁移影响和历史兼容。
- `TASK-BOARD.md`：写数据库设计、后端实现、迁移确认和测试验证由哪个任务负责。
- `TEST-CASES.md`：写与数据库设计相关的验证点、兼容场景和回归点。

## 推荐结构

`DATABASE-DESIGN.md` 至少包含：

1. 数据库设计目标
2. 涉及的数据对象
3. 表清单
4. 表关系说明
5. 字段草案
6. 主键和唯一约束
7. 索引建议
8. 枚举/字典映射
9. 数据迁移影响
10. 历史数据兼容方案
11. 待确认项

## 质量门槛

每个数据库设计条目至少说明：

- 设计编号，例如 `<a id="db-001"></a>[DB-001](DATABASE-DESIGN.md#db-001)`。
- 涉及的数据对象、表或字段。
- 变更目的和对应业务规则。
- 字段草案：名称、类型建议、长度建议、是否必填、默认值、含义、约束。
- 主键、唯一约束和数据关系。
- 索引建议及查询场景。
- 枚举或字典映射。
- 历史数据兼容策略。
- 是否涉及数据迁移、回填、清理或存量数据兜底。
- 待后端技术设计确认的内容。
- 关联业务规则、接口、任务和测试用例。

## 常见遗漏

- 把 `DATABASE-DESIGN.md` 写成最终 DDL 文件，而不是设计草案。
- 只写字段名，不写业务目的、约束、兼容策略和待确认项。
- 忽略历史数据、空值、重复数据、脏数据或迁移影响。
- 有查询口径变化，但没有索引建议和查询场景。
- 有枚举或字典映射，但没有说明值域、名称变化和兼容关系。
- 数据库设计没有映射到后端任务、测试用例或发布检查。
- 把 DDL、索引、迁移 SQL、回填 SQL 或回滚 SQL 写进 `BUSINESS-RULES.md`。
